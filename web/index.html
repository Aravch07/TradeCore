Measurement notes

Command duration measures the synchronous WebAssembly call, including C matching, simulator work and detailed trace generation. Snapshot formatting and dashboard rendering are excluded.

Benchmark throughput measures one call generating 1,000 simulated commands. It includes C order generation. It is device-dependent and is not a production exchange benchmark.

Reserved buffers is the C engine’s fixed storage footprint, not browser memory usage. History retains 2,048 fills; traces retain 128 events.

Use the native CLI’s bench 1000 for a separate native-C measurement. Native and browser timings are not directly comparable.

Explore the source
01

The matching rule

Highest bid, lowest ask. At the same price, the earliest accepted order goes first. Trades execute at the resting order’s price. An unmatched remainder waits at its limit.

Changing an order cancels its remaining quantity and creates a new order with new priority. The replacement quantity is the new remaining quantity.

02

The structures

AVL trees organize price levels. FIFO queues use doubly linked lists. A custom hash table finds active orders. Arrays retain fills and traces.

Level insert/delete is O(log P). Queue changes are O(1) once the node is known. Hash lookup is expected O(1), with O(N) worst-case collisions.

03

The C-first architecture

The exact same src/engine.c builds into a native CLI and a WebAssembly module. HTML, CSS and JavaScript display the interface and call exported C functions.

There is no JavaScript matching-engine fallback, Python bridge or hosted database. Vercel serves the static dashboard and compiled C module.

04

Your private simulation

This is a local order-book simulation, not a shared exchange. Each browser has its own session. Commands save on this device and can be exported and replayed.

No real money, live market feed, account balances, settlement or financial advice. All stocks and participants are fictitious.
